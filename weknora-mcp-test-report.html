05发现与建议

① 本机文件导入实际可用（推翻既有结论）

MCP server 以本机 venv 的 python.exe 通过 stdio 启动，MCP_ALLOWED_UPLOAD_DIRS 未设置时不做根目录限制，因此宿主 Windows 路径可直接导入，不存在「跨容器读不到本地路径」问题。

证据：4 个 C:\Users\…\.dsh\testbed\*.md/.txt/.csv 全部上传成功并解析完成

② 图谱白名单靠提示词即可收口，不依赖代码改动

在 tags 与 custom_instructions 中声明「关系 type 仅限五类」，抽取结果 114 条关系全部合规。此前计划的 Go 侧 RemoveUnknownRelation 补丁仍可作兜底，但对新库已非必需。

证据：Neo4j MATCH (a)-[r]->(b) RETURN type(r), count(*) → 仅返回 5 种类型，合计 114

③ MCP server 的 backfill 补丁已生效

update_extract_config 运行时返回的工具说明中已包含「Multimodal / ASR / parser-engine 表会先回填」段落，而该文案只存在于打补丁后的源码；调用后复查 get_knowledge_base 亦未见字段丢失。_backfill_initialization_config() 位于源码第 1291 行。

结论：上次会话遗留的第 ⑥ 项（重启 WorkBuddy 使补丁生效）已完成，无需再操作

④ CSV 摘要卡的「单行摘要」存在数字漂移

设备清单 Wiki 摘要页正文正确算出总额 497.2 万元（4,972,080 元），但其顶部 summary 字段写作「约 501.6 万元」，偏差约 4.4 万元。正文与引用块均准确，属单行摘要的模型近似误差。

建议：把单行摘要作为导航用，涉及金额/指标时以正文与 references 为准

⑤ Agent 回答前会输出英文过程叙述

agent_chat 的最终答案开头带有 "I'll research this by searching the knowledge base…" / "I have all the information needed…" 等中间过程文本，中文提问下略显突兀，且这部分不计入 references。

建议：如需干净输出，可在消费侧裁掉首个工具调用之前的过程文本

⑥ 图召回本次未参与最终引用

关系型提问（「吴敏和交付二部是什么关系」）返回的 match_type 全为 1/2，未出现图召回的 6。这与设计一致：图召回不参与 RRF 融合，仅做 append + 去重，常在向量已命中时贡献为 0。

判据提示：不要以「引用里有没有 match_type=6」判断图谱是否工作，应直接查 Neo4j 或服务日志的 entity search 计数

⑦ Wiki 合成模型未配置但页面照常生成

本库 wiki_config.synthesis_model_id 为空，但实体/概念/摘要页仍正常产出（68 页），仅 synthesis 与 comparison 两类页面数为 0。若需要主题综述/对比页，需补配该模型。

⑧ IDDC 库的 Go 侧补丁仍未生效（历史遗留）

本报告未触碰 IDDC。此前已确认：运行中服务是 v0.8.0，而本地源码为 v0.7.1，Go 补丁打在错误基线上；如需生效须先对齐 v0.8.0 基线再重建 app 镜像（本机无 Go 工具链，未编译验证）。
