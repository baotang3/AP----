## 1. 文档目的与范围

### 1.1 目的

本文档定义「六阶段 POC 流水线」的产品定位、业务模型、功能需求与验收标准，作为后续设计、开发、测试与验收的唯一天然语言依据。

### 1.2 范围

**包含：**

**A. 六阶段流水线（核心）**

- 六个阶段（AI 访谈 → 业务流程分析 → 业务需求分析 → 原型设计 → 数据库设计 → 低代码 POC）的完整流水线
- 阶段编排（切换、门禁、上游产出物传递）

- 行业模板（可配置）
- 项目 / 工作空间下的多流水线承载

**B. 原型中的配套功能模块（同样在范围内）**

- **资产库**：可复用项目资产的沉淀、检索、下载（见 7.11）
- **知识管理**：知识库的增删改查、文档管理、项目关联与检索（见 7.12）
- **智能集市**：智能体的发现与装配到项目（见 7.13）
- **预览面板**：产出物与文件的按类型预览（见 7.14）
- **项目分享**：项目分享给他人（见 7.10）

> **说明**：B 组模块在原型的 `AI-chat.html` 中均有完整的界面与数据形状（部分为空实现），是工作台的组成部分。本需求全部纳入，并按第 9 章的覆盖矩阵逐项核对，不做静默丢弃。

**不包含（本阶段）：**

- Java 网关（`dorbit-api`）相关能力与集成
- 阶段 1–5 已有实现（`C:\dorbit_ai`）的迁移或改造
- 多租户计费、审批工作流、运维监控大屏
- Agent 沙箱隔离的加固（属 AP_Hub 既有专项，不在本流水线范围）
- 资产库 / 知识库 / 集市条目的**运营后台**（上架、审核、用量报表）——本阶段只做消费端

## 2. 产品定位

### 2.1 一句话定位

**把「客户业务访谈」到「可运行 POC 应用」的全过程，变成一条由 AI Agent 逐步推进、产出物自动串联传递的流水线。**

### 2.2 解决的核心问题

现状（`C:\dorbit_ai`）的五个阶段能力**彼此孤立**：

- 阶段 1（需求访谈）有完整实现，但产出物只有自己知道；
- 阶段 2–5（业务流程 / 用户故事 / 原型 / 数据模型）在另一服务里，各自独立生成，**互不感知**；
- 前端是 5 个平级页面，用户可以任意顺序进入，**没有"上一步的结论自动成为下一步的输入"**；
- 阶段 6（低代码代码生成）**完全缺失**。

结果是：用户每进一个页面都要重新描述一遍业务背景；产出物之间的一致性靠人肉保证；到不了"可运行应用"这个终点。

### 2.3 本能力的价值主张

| 价值 | 说明 |
|---|---|
| 上下文自动传递 | 阶段 N 的 Agent 自动获得阶段 1..N-1 的结构化产出物，用户无需重复描述 |
| 过程可视 | 右侧「6 步流程指引」实时呈现每阶段状态、产出物数量与内容 |
| 结论可追溯 | 每个产出物保留完整生成历史与版本，可对比、可回滚 |
| 终点可交付 | 阶段 6 产出可运行的代码工程，而非停在文档 |
| 起步可加速 | 3 套行业模板可预填全部阶段产出物，演示与售前场景即开即用 |

## 3. 术语定义

| 术语 | 英文 / 标识 | 定义 |
|---|---|---|
| **阶段** | Stage | 软件工程的一个阶段，同时是 Agent 执行的一个阶段。共 6 个，固定不变 |
| **阶段标识** | `stage_key` | `interview` / `bpm` / `story` / `ui` / `db` / `lowcode` |
| **阶段序号** | `stage_order` | 1..6，用于判断上游与门禁 |
| **产出物** | Stage Artifact | 某阶段产出的业务实体。**区别于"文件"**：产出物是业务语义单元，文件是它的渲染载体 |
| **结构化内容** | `content_json` | 产出物的结构化源数据。**是阶段间传递的实际载体** |
| **渲染产物** | `file_id` | 产出物的可读载体（PDF / PNG / DOCX / ZIP），供人查看与下载 |
| **产出物标识** | `slug` | 阶段内稳定的产出物标识，如 `interview.summary`、`db.model` |
| **产出物类别** | `kind` | `document` / `diagram` / `json` / `dsl` / `code` / `dataset` / `image` |
| **版本** | version | 同一 `slug` 的历次生成。**必须完整保留** |
| **行业模板** | Stage Template | 一套预填的六阶段产出物内容，用于新建项目时快速起步 |
| **上游上下文** | Upstream Context | 阶段 N 执行时自动注入的、阶段 1..N-1 的 `content_json` 集合 |
| **门禁** | Gate | "进入下一步"的前置校验：上游阶段产出物必须就绪 |
| **失效传播** | Stale Propagation | 上游产出物被重新生成后，标记下游产出物为"待重新生成" |
| **切换策略** | Stage Switch Policy | 切阶段时是否重放上一阶段的对话记录。默认 `fresh` |

## 4. 六阶段模型

### 4.0 总览

```
                          ┌─────────────── 上游上下文 content_json ───────────────┐
                          │                                                       │
 ①interview ──▶ ②bpm ──▶ ③story ──▶ ④ui ──▶ ⑤db ──▶ ⑥lowcode ──▶ 可运行代码工程
   访谈        业务流程    业务需求    原型设计   数据库设计   低代码POC
                          │                                                       │
                          └─────────────── 收敛 ─▶ 展开 ──────────────────────────┘
                              前 4 阶段：给人看的业务语义
                              第 5 阶段：收敛为规范化数据模型（唯一机器可读契约）
                              第 6 阶段：由数据模型确定性展开为代码
```

**流水线本质是「收敛 → 展开」的漏斗**：前 4 阶段的产出物是面向人的业务描述；第 5 阶段把它们收敛成一份规范化数据模型；第 6 阶段由该模型机械展开成代码。**第 5 阶段的产出物是唯一同时具备"上游 AI 生成"与"下游机器消费"双重身份的契约**，因此其结构稳定性要求最高。

### 4.1 阶段定义

#### 阶段 1 · AI 访谈助手（`interview`，order=1）

| 项 | 内容 |
|---|---|
| **目标** | 通过引导式对话采集业务需求，沉淀为结构化需求实体 |
| **输入** | 用户自然语言；可选的上传资料（现有文档、问卷） |
| **产出物** | `interview.outline`（访谈提纲，document）<br>`interview.summary`（访谈总结，json + diagram）<br>`interview.spec`（需求规格说明书 / PRD，document） |
| **完成判据** | `interview.summary` 就绪 |
| **下游消费者** | 全部后续阶段 |

#### 阶段 2 · 业务流程分析（`bpm`，order=2）

| 项 | 内容 |
|---|---|
| **目标** | 基于访谈结论梳理业务流程地图 |
| **输入** | 阶段 1 上游上下文 |
| **产出物** | `bpm.map`（业务流程地图，json + diagram）—— **含 L1 / L2 / L3 三层** |
| **完成判据** | `bpm.map` 就绪且 L1、L2 非空 |
| **下游消费者** | 阶段 3、4、5 |

#### 阶段 3 · 业务需求分析（`story`，order=3）

| 项 | 内容 |
|---|---|
| **目标** | 将业务流程拆解为活动、接触点与业务需求 |
| **输入** | 上游上下文（阶段 1、2） |
| **产出物** | `story.map`（用户故事地图，json + diagram）<br>`story.prd`（PRD 需求文档，document） |
| **完成判据** | `story.map` 就绪且 `stories` 非空 |
| **下游消费者** | 阶段 4、5、6 |

#### 阶段 4 · 原型设计助手（`ui`，order=4）

| 项 | 内容 |
|---|---|
| **目标** | 基于业务需求生成界面原型 |
| **输入** | 上游上下文（阶段 1、2、3） |
| **产出物** | `ui.prototype`（原型说明 + 可运行 HTML 原型，json + image） |
| **完成判据** | `ui.prototype` 就绪且 `menus` 非空 |
| **下游消费者** | 阶段 6（菜单结构决定生成哪些页面） |

#### 阶段 5 · 数据库设计（`db`，order=5）★ 全链路契约

| 项 | 内容 |
|---|---|
| **目标** | 依据原型与业务需求设计数据模型 |
| **输入** | 上游上下文（阶段 1–4） |
| **产出物** | `db.model`（**数据模型 DSL**，dsl）<br>`db.diagram`（数据库设计图，diagram） |
| **完成判据** | `db.model` 就绪且 `tables` 非空、每表 `fields` 非空 |
| **下游消费者** | 阶段 6 |

> **特别约束**：`db.model` 的结构必须与阶段 6 代码生成器的输入契约为同一份定义（见《02-规则文档》第 6 章）。

#### 阶段 6 · 低代码 POC（`lowcode`，order=6）

| 项 | 内容 |
|---|---|
| **目标** | 由数据模型确定性生成可运行的代码工程 |
| **输入** | 阶段 5 的 `db.model`（必需）；阶段 4 的 `ui.prototype.menus`、阶段 3 的 `story.map`（增强） |
| **产出物** | `lowcode.codegen`（代码工程包，code）<br>`lowcode.manifest`（生成清单，json） |
| **完成判据** | `lowcode.codegen` 就绪且打包成功 |
| **下游消费者** | 无（终点） |

> **本阶段的性质与前 5 阶段不同**：它是**确定性生成**，不由 LLM 自由创作，而是模板引擎按固定规则展开。LLM 的职责在阶段 5 结束。

### 4.2 阶段交互模式（★ 重要）

六个阶段的交互形态**不是同一种**，必须区分对待：

| 阶段 | 交互模式 | 说明 |
|---|---|---|
| ① `interview` | **访谈引导式** | 唯一的交互式阶段。Agent 主动提问、逐轮采集、沉淀结构化实体。上游无产出物，上下文来自用户与上传资料 |
| ② `bpm` | **直接生成** | 不提问。读取上游产出物后**一次性生成**业务流程地图 |
| ③ `story` | **直接生成** | 不提问。读取上游产出物后一次性生成用户故事地图与 PRD |
| ④ `ui` | **直接生成** | 不提问。读取上游产出物后一次性生成原型 |
| ⑤ `db` | **直接生成** | 不提问。读取上游产出物后一次性生成数据模型 DSL |
| ⑥ `lowcode` | **直接生成（确定性）** | 不提问，且**不经 LLM 推理**。由数据模型经模板引擎机械展开 |

**由此产生的约束：**

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-MODE-01 | **只有阶段 1 需要多轮提问引导**；阶段 2–6 **必须**支持"一键生成"——用户点击操作按钮即产出结果，不得强制多轮对话 | 必须 |
| FR-MODE-02 | 阶段 2–5 生成后，用户**可以**继续用自然语言要求局部修改（对应原型中"只改目标项、其余保持不变"的交互），但这属**可选增强**，不得作为生成的前置条件 | 必须 |
| FR-MODE-03 | 阶段 1 的引导式提问**必须**基于结构化的问题清单推进（问题顺序由阶段定义或本体决定），不得完全自由发挥 | 应该 |
| FR-MODE-04 | 阶段 2–6 在缺少必要上游产出物时，**必须**给出明确提示并引导用户先完成上游，**不得**在信息不足时凭空生成 | 必须 |
| FR-MODE-05 | 阶段 1–5 的生成过程**必须**以流式方式呈现进度，避免用户面对长时间空白等待 | 必须 |
| FR-MODE-06 | 阶段 6 为确定性生成，其进度**必须**以步骤 / 进度形式呈现（而非 token 流式） | 应该 |

> **对设计的影响**：阶段 2–6 的 Agent 提示词应写成"生成器"形态（输入 → 结构化输出），而非"访谈者"形态。原型中 `agentSteps` 为每个阶段都配了多轮问答脚本，**这是原型的过度设计**，本需求不采纳。

### 4.3 已定型的阶段相关决策

| 编号 | 事项 | 决策 |
|---|---|---|
| **Q1** | 阶段 6 生成代码的 Vue 版本 | **Vue 3**（对齐 `ap_agent_ui`，不沿用原型样本中的 Vue 2） |
| **Q2** | 数据模型画布（ER 图）的坐标 | **由后端确定性布局算法计算**，不由 AI 生成 |
| **Q3** | 各阶段的交互模式 | **仅阶段 1 需要提问**，阶段 2–6 直接生成（见 4.2） |
| **Q4** | 长文本产出物的压缩阈值与策略 | 采用建议默认值并留配置项（阈值待设计阶段定） |
| **Q5** | 「待重新生成」标记的清除方式 | **随重新生成自动清除**，不需用户手动操作 |
| **Q6** | 知识库检索的实现方式 | **暂只做接口，不做功能引入**（边界见 Q6a） |
| **Q6a** | Q6 的边界 | 知识库的**数据模型、后端 CRUD 接口、前端界面全部实现**；**仅**不引入向量库 / 嵌入模型 / 切片与相似度计算，`IF-KB-06` 返回"未启用" |
| **Q7** | 资产内容的存储形态 | **文件包** |
| **Q8** | 智能集市与既有 Skill 体系的关系 | **沿用 AP_Hub 既有机制**，不新造体系 |
| **Q9** | 知识库的「文档」是否复用既有文件体系 | **复用** |
| **Q10** | 项目分享的对象列表 | **复用** AP_Hub 既有用户体系 |
| **Q11** | 模块交付顺序 | **分批交付**（批次划分见 12.1） |

## 5. 用户角色

## 6. 核心用户场景

| 编号 | 场景 | 说明 |
|---|---|---|
| **S1** | **从零启动 POC 项目** | 新建项目（空白或选行业模板）→ 进入阶段 1 → 完成访谈 → 依次推进至阶段 6 |
| **S2** | **模板快速起步** | 新建项目时选择行业模板，六阶段产出物被预填 → 用户在此基础上局部修改 → 直接跳到某一阶段工作 |
| **S3** | **产出物局部修改** | 在某阶段内用自然语言要求修改（如"把第二个节点改成 XX"）→ 仅目标内容变化，其余保持不变 → 形成新版本 |
| **S4** | **回溯与版本对比** | 查看某产出物的历史版本 → 对比差异 → 回滚到任意历史版本 |
| **S5** | **上游变更后的下游处理** | 重新生成阶段 2 产出物 → 下游（3–6）产出物被标记"待重新生成" → 用户选择性地重新生成 |
| **S6** | **产出物查看与交付** | 在右侧"产出物"Tab 中筛选/搜索/下载；点击产出物进行预览；批量下载交付 |
| **S7** | **阶段回退** | 已推进到阶段 5，发现业务流程有问题 → 切回阶段 2 修改 → 再前进 |

## 7. 功能需求

需求编号规则：`FR-<域>-<序号>`。域：`PRJ`（项目）`PIPE`（流水线）`ART`（产出物）`CTX`（上下文）`TPL`（模板）`UI`（界面）`SEC`（权限）。

### 7.1 项目管理（PRJ）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-PRJ-01 | 用户可在工作空间下创建项目，指定名称、描述 | 必须 |
| FR-PRJ-02 | 创建项目时可选择「空白」或某个行业模板 | 必须 |
| FR-PRJ-03 | 选择模板时，系统将模板内容逐阶段写入该项目的产出物，标记来源为"模板"、版本为 1 | 必须 |
| FR-PRJ-04 | 项目下可存在多个对话；每个对话独立绑定一个阶段 | 必须 |
| FR-PRJ-05 | 项目可归档；归档后不可发起新的 Agent 执行，产出物仍可查看下载 | 应该 |
| FR-PRJ-06 | 项目列表展示各阶段完成情况与总体进度 | 必须 |

### 7.2 六阶段流水线（PIPE）

| 编号 | 需求 | 优先级 |
|---|---|---|

>
> **边界确认（Q6a）**：知识库的**数据模型、后端 CRUD 接口、前端界面全部实现**；"不做功能引入"**仅指**不引入向量库、嵌入模型、切片与相似度计算。**不得**解释为"连表都不建"。

## 12. 交付批次划分（Q11：分批交付）

### 12.1 批次边界

**第一批（本设计文档的重点）—— 六阶段 POC 流水线**

| 范围 | 内容 |
|---|---|

| 产出物 | 跨阶段统一产出物台账、双层内容、Schema 校验、完整版本历史与回滚、失效传播 |
| 上下文 | 上游产出物自动注入、指纹控频、切换后强制重注入 |
| 模板 | 可配置行业模板 + 3 套内置模板 |

| 界面 | 三栏工作台、6 步流程指引、产出物 Tab、工作空间文件树、**按阶段派发的操作按钮**、预览面板 |
| 项目 | 项目 CRUD、项目列表与进度 |

**第二批 —— 配套模块**

| 范围 | 内容 |
|---|---|
| 资产库 | 元信息管理、搜索筛选、**文件包**存储（Q7）、查看 / 编辑 / 下载（含真实的打包下载） |
| 知识管理 | 知识库与文档的元信息管理（Q9 复用既有文件体系）、**接口就位但检索未启用**（Q6） |
| 智能集市 | **沿用 AP_Hub 既有 Skill 机制**（Q8）：条目基于既有技能体系构建，「立即使用」装配为项目级技能 |
| 项目分享 | 分享关系与权限校验，对象列表**复用既有用户体系**（Q10） |

> **批次原则**：第一批必须能**独立完整交付并验收**——即不依赖任何第二批模块即可走通六个阶段。这正是规则 **R-MOD-01** 的要求。第二批模块在第一阶段只需保证**接口契约已定义**（《01-需求文档》第 8 章），不得在第一阶段实现其功能。
>
> **设计文档范围（已确认）**：第一批的《03-设计文档》**必须完整包含第二批模块的接口设计**——即第 8 章全部 `IF-*` 接口的入参、出参、错误语义、降级行为都要在第一批设计阶段定清。目的是让第二批可独立并行开发、不返工。对应的强制规则为 **R-ENG-11 / R-ENG-12**。
>
> **降级契约要求**：第二批功能未实现期间，前端与编排层**只能依赖"未启用"语义降级**正常工作，**不得**为"暂未实现"写临时分支（R-ENG-12）。

## 13. 验收标准

### 13.1 端到端主流程（S1）

从空白项目开始，依次完成六个阶段，满足：

1. 每次切换阶段，AI 均能正确识别当前角色与产出物类型；
2. 进入阶段 N 时，AI 的回复中体现已读取阶段 1..N-1 的产出物；
3. 每个阶段结束时，对应产出物被持久化，刷新页面后仍存在；
4. 右侧「流程指引」的产出物数量、状态徽标与实际情况一致；
5. 展开某步骤时，看到的是该项目该阶段的**真实产出物内容**；
6. 阶段 6 结束时产生可下载的代码工程包。

### 13.2 关键场景验收

| 场景 | 验收点 |
|---|---|
| S2 模板起步 | 选模板创建后，6 个阶段立即可见预填产出物；可直接进入任一阶段工作 |
| S3 局部修改 | 用自然语言要求修改后，仅目标内容变化，其余字段完全一致；产生新版本且旧版本可查 |
| S4 版本对比 | 任一产出物的历史版本全部可列出、可查看、可回滚；回滚产生新版本而非删除 |
| S5 上游变更 | 重新生成阶段 2 后，阶段 3–6 产出物被标记"待重新生成"且未被自动删除或重算 |
| S6 产出物交付 | 可筛选、搜索、多选、批量下载；点击可预览 |
| S7 阶段回退 | 从阶段 5 回退到阶段 2，门禁不阻止；修改后再次前进时，"进入下一步"按新内容重新判定 |

### 13.3 非功能验收

| 项 | 验收点 |
|---|---|
| 上下文注入频率 | 上游未变化时，连续多轮对话不重复注入上游内容（可通过日志验证） |
| 阶段切换确定性 | 反复切换阶段并对话，行为一致，不出现"有时重放有时不重放" |
| 权限 | 跨用户访问他人项目的产出物、切换他人对话的阶段，均被拒绝 |
| Schema 校验 | 构造不符合 Schema 的产出物输入，系统拒绝保存并向 Agent 返回可修正的错误 |
| 向后兼容 | AP_Hub 既有功能（文件、Skill、对话、产出物面板）回归无异常 |
| 资产库 | 6 条内置资产可列出、可搜索、可按类别筛选；查看 / 编辑 / 下载三个操作均可用（不再是空壳）；资源数量与实际情况一致 |
| 知识管理 | 知识库可新建、可编辑、可删除；文档可上传并正确显示解析状态；删除文档后检索不再命中；知识库可关联到项目，且关联后在 Agent 执行中检索生效 |
| 智能集市 | 条目可列出、可搜索、可按六类筛选；点「立即使用」后智能体出现在工作空间「技能」分组，且**在后续对话中真正可被调用**；重复使用不产生重复条目；使用次数随实际调用增长 |
| 预览面板 | 打开真实文件可正确渲染；不支持的类型给出提示与下载入口而非伪造内容；同一文件重复打开不产生重复 Tab |
| 项目分享 | 分享对象来自真实用户而非写死列表；被分享者可按授权访问；取消分享后立即失效 |
| 模块降级 | 关闭知识库 / 资产库 / 集市任一模块，六阶段流水线仍可完整走通 |
| 交互模式区分 | 阶段 2–6 均可**一键生成**，不强制多轮对话；阶段 1 为引导式提问（FR-MODE-01） |
| 缺上游保护 | 阶段 2–6 在缺必要上游产出物时给出明确提示，不凭空生成（FR-MODE-04） |
| 未启用检索的降级 | `IF-KB-06` 返回"未启用"时，编排层降级为无知识库上下文，Agent 执行不被中断（R-KB-10） |
| 批次独立性 | 在第二批模块全部未实现的情况下，第一批（六阶段流水线）可独立完整验收 |
