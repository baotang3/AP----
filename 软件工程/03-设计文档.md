### 1.2 分层设计原则

| 原则 | 说明 | 依据 |
|---|---|---|
| **编排与执行分离** | 阶段切换、门禁、上下文组装属编排层；Agent 执行属既有 SDK 服务 | R-ARCH-12 |
| **Schema 即契约** | 6 份 JSON Schema 是产出物结构的唯一真源，驱动校验、提示词、文档 | R-ART-05、NFR-M-01 |
| **语义层与渲染层分离** | `content_json` 传下游，`file_id` 给人看 | R-ART-01~04 |
| **产出物台账与文件登记分离** | 新表管业务语义；`harness_artifacts` + FileWatcher 管文件事实，二者通过 `file_id` 汇合 | R-ARCH-08/09 |
| **阶段配置外置** | 阶段定义、提示词、操作按钮全在配置，核心编排代码不含业务文案 | R-ARCH-10、R-STAGE-16 |
| **第二批只留接口** | 第二批模块的接口在本批完整定义，功能不实现，调用方靠"未启用"降级 | R-ENG-11/12 |

## 2. 数据模型设计

### 2.1 设计决策说明

| 决策 | 选择 | 理由 | 依据 |
|---|---|---|---|
| 产出物归属 | 挂在 `project_id` | 产出物是项目资产，多对话可共享 | R-DATA-06 |
| 阶段指针位置 | 挂在 `conversation` | prompt 是 conversation 级缓存的；同一项目可并行探索多个阶段 | R-STAGE-01 |
| 阶段状态 | 不建表、不落库 | 从产出物派生；避免"状态说完成但无产出物" | R-DATA-15/16 |
| 版本建模 | 主表 + 版本表（指针式） | 主表存"当前是什么"供下游快速取用；版本表存"曾经是什么" | D3、R-ART-09 |
| 模板建模 | 独立全局表 + `payload_json` | 模板不属任何项目；内容即各阶段产出物 | R-DATA-17 |
| 长文本 | 双列（明文 + gzip） | 支持按字段查询的同时避免膨胀 | R-DATA-13、NFR-S-01 |

### 2.2 `harness_stage_artifacts`（产出物主表）

```sql
CREATE TABLE harness_stage_artifacts (
  guid            VARCHAR(32)  NOT NULL COMMENT '主键',
  project_id      VARCHAR(32)  NOT NULL COMMENT '所属项目',
  conversation_id VARCHAR(32)  NULL     COMMENT '产出该产出物的对话',

  -- 阶段维度（stage_order 为冗余列，避免查询时解析配置）
  stage_key       VARCHAR(32)  NOT NULL COMMENT 'interview|bpm|story|ui|db|lowcode',
  stage_order     INT          NOT NULL COMMENT '1..6，冗余便于排序与门禁',

  -- 产出物身份
  slug            VARCHAR(64)  NOT NULL COMMENT '阶段内稳定标识，如 interview.summary',
  kind            VARCHAR(32)  NOT NULL COMMENT 'document|diagram|json|dsl|code|dataset|image',
  title           VARCHAR(255) NOT NULL COMMENT '显示标题',

  -- 双层内容
  content_json    JSON         NULL     COMMENT '结构化内容（语义层，喂下游）',
  content_text    LONGTEXT     NULL     COMMENT '长文本明文（便于 LIKE 检索）',
  content_gzip    LONGBLOB     NULL     COMMENT '长文本 gzip（体积最优，读取时优先）',
  content_hash    VARCHAR(64)  NOT NULL COMMENT 'sha256，判断内容是否真变化',
  file_id         VARCHAR(32)  NULL     COMMENT '渲染产物（PDF/PNG/ZIP），→ harness_files',

  -- 版本与状态
  current_version INT          NOT NULL DEFAULT 1,
  is_active       BOOLEAN      NOT NULL DEFAULT TRUE  COMMENT '同 slug 仅一个 TRUE',
  is_archived     BOOLEAN      NOT NULL DEFAULT FALSE COMMENT '归档=不再被下游引用，不删除',
  is_stale        BOOLEAN      NOT NULL DEFAULT FALSE COMMENT '上游已更新，待重新生成',
  status          VARCHAR(20)  NOT NULL DEFAULT 'draft' COMMENT 'draft|generating|ready|failed',

  -- 追溯
  source          VARCHAR(32)  NOT NULL DEFAULT 'agent' COMMENT 'agent|template|upload|manual|imported',
  source_service  VARCHAR(64)  NULL     COMMENT '来源服务，如 qinwen/codegen（前身实现迁移用）',
  run_id          VARCHAR(32)  NULL     COMMENT '产出它的 AgentRun → harness_agent_runs',
  stale_reason    VARCHAR(255) NULL     COMMENT '失效原因，如 "阶段2的bpm.map已更新"',
  meta            JSON         NULL     COMMENT '尺寸/页数/表数/耗时/token 等',

  created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at      DATETIME     NULL,

  PRIMARY KEY (guid),
  UNIQUE KEY uq_stage_artifact (project_id, slug, current_version),
  KEY idx_sa_project_stage (project_id, stage_key, stage_order),
  KEY idx_sa_active (project_id, slug, is_active),
  KEY idx_sa_ready (project_id, stage_order, is_active, status),
  KEY idx_sa_run (run_id),
  KEY idx_sa_file (file_id),
  CONSTRAINT fk_sa_project      FOREIGN KEY (project_id)      REFERENCES harness_projects(guid)      ON DELETE CASCADE,
  CONSTRAINT fk_sa_conversation FOREIGN KEY (conversation_id) REFERENCES harness_conversations(guid) ON DELETE SET NULL,
  CONSTRAINT fk_sa_run          FOREIGN KEY (run_id)          REFERENCES harness_agent_runs(guid)    ON DELETE SET NULL,
  CONSTRAINT fk_sa_file         FOREIGN KEY (file_id)         REFERENCES harness_files(guid)         ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='阶段产出物（跨阶段统一台账）';
```

**关键约束说明：**

- `uq_stage_artifact (project_id, slug, current_version)`：**数据库级**保证"同 slug 同版本号只有一条"（R-DATA-09）。
- `idx_sa_ready (project_id, stage_order, is_active, status)`：专为**上游上下文查询**设计——`WHERE project_id=? AND stage_order<? AND is_active=1 AND status='ready'`，走覆盖索引，满足 `NFR-P-01`（≤1 次往返）。
- `content_hash` 用于 `R-ART-11`（哈希未变不产生新版本）。

### 2.3 `harness_stage_artifact_versions`（版本快照）

```sql
CREATE TABLE harness_stage_artifact_versions (
  guid          VARCHAR(32)  NOT NULL,
  artifact_id   VARCHAR(32)  NOT NULL COMMENT '→ harness_stage_artifacts',
  version       INT          NOT NULL,
  content_json  JSON         NULL,
  content_text  LONGTEXT     NULL,
  content_gzip  LONGBLOB     NULL,
  content_hash  VARCHAR(64)  NOT NULL,
  file_id       VARCHAR(32)  NULL     COMMENT '该版本的渲染产物',
  change_note   VARCHAR(500) NULL     COMMENT '如「已将第2个子流程改名X，其余保持不变」',
  change_source VARCHAR(32)  NOT NULL DEFAULT 'agent' COMMENT 'agent|manual|rollback|template',
  created_by    VARCHAR(64)  NULL,
  run_id        VARCHAR(32)  NULL     COMMENT '产出该版本的一次执行',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,

  PRIMARY KEY (guid),
  UNIQUE KEY uq_sav (artifact_id, version),
  KEY idx_sav_artifact (artifact_id, version DESC),
  CONSTRAINT fk_sav_artifact FOREIGN KEY (artifact_id) REFERENCES harness_stage_artifacts(guid) ON DELETE CASCADE,
  CONSTRAINT fk_sav_file     FOREIGN KEY (file_id)     REFERENCES harness_files(guid)           ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='阶段产出物版本快照（只增不改不删）';
```

> **只增不改不删**（R-DATA-11）。回滚实现为"以历史内容创建新版本"（`change_source='rollback'`），**不删除**回滚点之后的版本（R-ART-13）。

### 2.6 ORM 模型（Python）

```python
# app/models/stage_artifact.py
"""阶段产出物模型。

三层结构：
  StageArtifact          当前状态（下游取用入口，只查这一层）
  StageArtifactVersion   历史快照（只增不改不删）
  StageTemplate          行业模板（全局，不属项目）

与 harness_artifacts 的分工：
  本表 = 业务语义单元（有 stage/slug/结构化内容/版本）
  harness_artifacts = 文件变更事实（FileWatcher 自动登记）
  二者通过 file_id 汇合，互不替代。
"""

class StageArtifact(Base, GUIDMixin, TimestampMixin):
    __tablename__ = "harness_stage_artifacts"

    project_id:      Mapped[str]      = mapped_column(String(32), ForeignKey("harness_projects.guid", ondelete="CASCADE"), nullable=False)
    conversation_id: Mapped[str|None] = mapped_column(String(32), ForeignKey("harness_conversations.guid", ondelete="SET NULL"), nullable=True)
    stage_key:       Mapped[str]      = mapped_column(String(32), nullable=False, comment="interview|bpm|story|ui|db|lowcode")
    stage_order:     Mapped[int]      = mapped_column(Integer, nullable=False, comment="1..6")
    slug:            Mapped[str]      = mapped_column(String(64), nullable=False)
    kind:            Mapped[str]      = mapped_column(String(32), nullable=False)
    title:           Mapped[str]      = mapped_column(String(255), nullable=False)
    content_json:    Mapped[dict|None]= mapped_column(JSON, nullable=True)
    content_text:    Mapped[str|None] = mapped_column(LONGTEXT, nullable=True)
    content_gzip:    Mapped[bytes|None]=mapped_column(LONGBLOB, nullable=True)
    content_hash:    Mapped[str]      = mapped_column(String(64), nullable=False)
    file_id:         Mapped[str|None] = mapped_column(String(32), ForeignKey("harness_files.guid", ondelete="SET NULL"), nullable=True)
    current_version: Mapped[int]      = mapped_column(Integer, nullable=False, default=1)
    is_active:       Mapped[bool]     = mapped_column(Boolean, nullable=False, default=True)
    is_archived:     Mapped[bool]     = mapped_column(Boolean, nullable=False, default=False)
    is_stale:        Mapped[bool]     = mapped_column(Boolean, nullable=False, default=False)
    status:          Mapped[str]      = mapped_column(String(20), nullable=False, default="draft")
    source:          Mapped[str]      = mapped_column(String(32), nullable=False, default="agent")
    source_service:  Mapped[str|None] = mapped_column(String(64), nullable=True)
    run_id:          Mapped[str|None] = mapped_column(String(32), ForeignKey("harness_agent_runs.guid", ondelete="SET NULL"), nullable=True)
    stale_reason:    Mapped[str|None] = mapped_column(String(255), nullable=True)
    meta:            Mapped[dict|None]= mapped_column(JSON, nullable=True)

    versions: Mapped[list["StageArtifactVersion"]] = relationship(
        back_populates="artifact", lazy="selectin",
        cascade="all, delete-orphan", order_by="StageArtifactVersion.version.desc()",
    )
    file: Mapped["File|None"] = relationship()

    __table_args__ = (
        UniqueConstraint("project_id", "slug", "current_version", name="uq_stage_artifact"),
        Index("idx_sa_project_stage", "project_id", "stage_key", "stage_order"),
        Index("idx_sa_active", "project_id", "slug", "is_active"),
        Index("idx_sa_ready", "project_id", "stage_order", "is_active", "status"),
    )
```

> `StageArtifactVersion` 与 `StageTemplate` 同文件，字段对应 2.3 / 2.4 的 DDL。
> **注意**：`lazy="selectin"` 便于一次带出版本，但列表查询时会造成 N+1 放大——列表接口须显式 `noload(StageArtifact.versions)`，仅详情接口用 `selectinload`。

### 3.1 阶段 1 · 访谈（`interview`）

```python
class InterviewOutline(BaseModel):
    """访谈提纲。渲染为 PDF（对应样本 assets/访谈提纲.pdf）。"""
    title: str = Field(..., description="提纲标题")
    sections: list[OutlineSection] = Field(..., min_length=1, description="提纲章节，建议 8 个模块")

class OutlineSection(BaseModel):
    key: str = Field(..., description="章节标识，如 strategy/stakeholders")
    title: str
    title_en: str | None = None
    questions: list[str] = Field(..., min_length=1)


class InterviewSummary(BaseModel):
    """访谈总结。驱动右栏统计卡与要点列表（对应样本 assets/访谈总结.png）。"""
    title: str
    summary: str = Field(..., description="一段话总结")
    completion: float = Field(0, ge=0, le=100, description="完成度百分比")
    stats: InterviewStats
    sections: list[InterviewSection] = Field(..., min_length=1)

class InterviewStats(BaseModel):
    objects: int = Field(0, ge=0, description="业务对象数")
    features: int = Field(0, ge=0, description="功能特征数")
    rules: int = Field(0, ge=0, description="业务规则数")
    categories: int = Field(0, ge=0, description="类别数")

class InterviewSection(BaseModel):
    key: Literal["goal", "users", "features", "tech", "constraints"]
    title: str = Field(..., description="业务目标 / 主要用户 / 功能场景 / 系统技术 / 限制条件")
    title_en: str | None = None
    points: list[str] = Field(..., min_length=1)

class InterviewSpec(BaseModel):
    """需求规格说明书（PRD）。"""
    title: str
    background: str
    scope: str
    functional_requirements: list[SpecRequirement] = Field(..., min_length=1)
    non_functional_requirements: list[str] = Field(default_factory=list)
    constraints: list[str] = Field(default_factory=list)

class SpecRequirement(BaseModel):
    code: str = Field(..., description="需求编号，如 FR-001")
    name: str
    description: str

### 5.2 上游上下文组装（`pipeline/context_builder.py`）

```python
async def build_upstream_context(
    db: AsyncSession, project_id: str, stage_key: str
) -> tuple[list[UpstreamItem], str]:
    """组装上游上下文并计算指纹。

    返回 (items, fingerprint)。items 为空时 fingerprint 为 EMPTY_HASH。

    性能：单次查询，命中 idx_sa_ready 覆盖索引（NFR-P-01）。
    过滤：仅 is_active AND status='ready' AND NOT is_archived（R-CTX-01、R-ART-15/16）
    """
    order = STAGE_ORDER[StageKey(stage_key)]
    rows = (await db.execute(
        select(StageArtifact)
        .options(noload(StageArtifact.versions))          # 避免版本表放大
        .where(
            StageArtifact.project_id == project_id,
            StageArtifact.stage_order < order,
            StageArtifact.is_active.is_(True),
            StageArtifact.is_archived.is_(False),
            StageArtifact.status == ArtifactStatus.READY,
            StageArtifact.deleted_at.is_(None),
        )
        .order_by(StageArtifact.stage_order, StageArtifact.slug)
    )).scalars().all()

    items = [
        UpstreamItem(
            stage_key=r.stage_key, slug=r.slug, title=r.title,
            content_json=r.content_json,
            content_text=decompress(r.content_gzip) if r.content_gzip else r.content_text,
            version=r.current_version,
        )
        for r in rows
    ]
    return items, compute_fingerprint(items)   # sha256 of canonical JSON


def render_context_block(items: list[UpstreamItem], budget: TokenBudget) -> str:
    """渲染为注入用的文本块。超预算时压缩（R-CTX-07 / NFR-P-02）。

    压缩策略（按优先级）：
      1. content_json 原样保留（结构化字段是下游必需）
      2. content_text 截断到预算内，保留头部
      3. 仍超限 → 只保留 content_json，并对长列表截断，标注 "[已截断 N 项]"
    """
    if not items:
        return ""
    parts = ["<upstream_artifacts>",
             "以下是本项目上游阶段的产出物，请作为本次任务的输入上下文。"]
    for it in items:
        parts.append(f"\n## [{it.stage_key}] {it.title} (slug={it.slug}, v{it.version})")
        if it.content_json is not None:
            parts.append("```json\n"
                         + json.dumps(it.content_json, ensure_ascii=False, indent=2)
                         + "\n```")
        if it.content_text:
            parts.append(it.content_text[: budget.text_chars])
    parts.append("</upstream_artifacts>")
    return "\n".join(parts)
```

### 5.3 注入位置与频率控制

```python
async def compose_run_input(conv: Conversation, user_message: str) -> str:
    """组装本次 run 的输入。

    注入策略（R-CTX-04/05/06）：
      - 注入在 run 级输入，不进系统提示词（避免上游变化导致频繁重连）
      - 指纹未变 → 不重复注入（控制 token）
      - 首次进阶段 / 切换阶段后 → 强制注入
    """
    items, fingerprint = await build_upstream_context(
        db, conv.project_id, conv.current_stage_key or StageKey.INTERVIEW
    )
    if fingerprint == conv.upstream_context_hash:
        return user_message                       # 已注入过，跳过（R-CTX-05）

    block = render_context_block(items, settings.context_token_budget)
    # 更新指纹（下次跳过）
    await conversation_repo.set_upstream_hash(conv.guid, fingerprint)

    if not block:
        return user_message
    return f"{block}\n\n---\n\n{user_message}"
```

**为什么放在 run 级而不是系统提示词级**（R-CTX-04）：

| 方案 | 问题 |
|---|---|
| 放系统提示词 | 上游产出物变化 → `prompt_hash` 变化 → 客户端重建 → 连接抖动。而上游变化比阶段切换频繁得多 |
| **放 run 级输入**（采用） | 客户端稳定；只有本轮的输入不同；指纹控制频率 |

### 5.5 失效传播（`pipeline/stale.py`）

```python
async def propagate_stale(db, project_id: str, changed_slug: str) -> list[str]:
    """上游产出物变更后，标记下游产出物为待重新生成（R-ART-17 / FR-STALE-01~04）。

    要点：
      - 只标记，不删除、不自动重算（R-ART-17 / R-STALE-02）
      - 标记信息含原因，供前端提示
      - 清除时机：该产出物被重新生成时自动清除（Q5 / R-ART-18）
    """
    changed = await _get_artifact(db, project_id, changed_slug)
    affected = (await db.execute(
        select(StageArtifact).where(
            StageArtifact.project_id == project_id,
            StageArtifact.stage_order > changed.stage_order,
            StageArtifact.is_active.is_(True),
            StageArtifact.deleted_at.is_(None),
        )
    )).scalars().all()

    for a in affected:
        a.is_stale = True
        a.stale_reason = f"上游 {changed.title}（{changed.slug} v{changed.current_version}）已更新"
    await db.commit()
    return [a.slug for a in affected]
```

### 5.6 产出物保存（`services/stage_artifact_service.py`）

```python
async def save_stage_artifact(
    db, *, project_id, conversation_id, stage_key, slug,
    content_json=None, content_text=None, file_id=None,
    change_note=None, source="agent", run_id=None, user_id=None,
) -> StageArtifact:
    """保存阶段产出物。核心流程（R-ART-05~15）。

    1. Schema 校验 → 失败抛 SchemaValidationError（携带结构化错误，R-ART-07）
    2. 计算内容哈希 → 与当前版本相同则直接返回，不产生新版本（R-ART-11）
    3. 事务内：锁定当前版本 → 置 is_active=False
              → 插入新版本记录
              → 主表 current_version+1 / is_active=True / is_stale=False（Q5）
              → 写 soft-delete 保护
    4. 事务外：propagate_stale + 发事件 stage_artifact_saved
    """
    model = SLUG_SCHEMA_REGISTRY.get(slug)
    if model is None:
        raise UnknownSlugError(slug)
    validated = model.model_validate(content_json) if content_json is not None else None

    payload = validated.model_dump() if validated else None
    new_hash = compute_hash(payload, content_text, file_id)

    async with db.begin_nested():
        current = await _lock_current(db, project_id, slug)   # SELECT … FOR UPDATE
        if current and current.content_hash == new_hash:
            return current                                     # 内容未变，R-ART-11

        version = (current.current_version + 1) if current else 1
        if current:
            current.is_active = False

        artifact = StageArtifact(
            project_id=project_id, conversation_id=conversation_id,
            stage_key=stage_key, stage_order=STAGE_ORDER[StageKey(stage_key)],
            slug=slug, kind=_kind_of(slug), title=_title_of(slug),
            content_json=payload,
            content_text=content_text,
            content_gzip=gzip.compress(content_text.encode()) if _should_compress(content_text) else None,
            content_hash=new_hash, file_id=file_id,
            current_version=version, is_active=True, is_archived=False,
            is_stale=False, stale_reason=None,        # ★ Q5：随重新生成自动清除
            status=ArtifactStatus.READY, source=source, run_id=run_id,
        )
        db.add(artifact)
        db.add(StageArtifactVersion(
            artifact_id=artifact.guid, version=version,
            content_json=payload, content_text=content_text,
            content_gzip=artifact.content_gzip, content_hash=new_hash,
            file_id=file_id, change_note=change_note or "初次生成",
            change_source=source, run_id=run_id, created_by=user_id,
        ))

    await db.commit()
    await propagate_stale(db, project_id, slug)
    await event_bus.publish("stage_artifact_saved", {...})
    return artifact
```

> **并发安全**：`_lock_current` 用 `SELECT … FOR UPDATE` 锁住同 slug 的当前版本行，防止并发写产生版本号冲突。配合 `uq_stage_artifact` 数据库唯一约束形成双保险（R-DATA-09、R-ENG-08）。

### 6.4 确定性布局（`generator/layout.py`）

```python
def layout_tables(tables: list[DbTable], *, cols: int = 3,
                  dx: float = 300.0, dy: float = 260.0) -> None:
    """确定性 ER 布局：按外键拓扑排序，网格铺开，就地写回 table.graph。

    为什么必须确定性（R-GEN-06）：
      历史上曾出现所有表沿一条 100px 斜线排布（Left=Top=n*100），
      根因是坐标由上游 AI/网关生成。改为确定性算法后：
        - 同一输入必得同一输出（可测、可复现）
        - 不存在退化排布
        - 与阶段6生成的内容无关（坐标只是渲染信息）

    算法：
      1. 按外键入度为 0 的表优先（拓扑序），使主表靠左
      2. 同层按表名字典序，保证稳定
      3. 网格铺开 (col, row) → left = 40 + col*dx, top = 20 + row*dy
    """
    ordered = _topological_order(tables)
    for i, t in enumerate(ordered):
        col, row = i % cols, i // cols
        t.graph = DbGraph(left=40.0 + col * dx, top=20.0 + row * dy)
```

### 6.5 生成流程

```python
async def generate_codegen(
    db, project_id: str, *, module_name: str | None = None
) -> StageArtifact:
    """阶段 6 主入口。

    1. 读阶段5的 db.model（必需）+ 阶段4的 ui.prototype.menus（增强）
    2. 后端确定性布局（Q2）
    3. 逐表套模板生成文件 → 写入工作空间临时目录
    4. 打包 zip → 通过既有文件服务落库 → 得到 file_id
    5. 构建 LowcodeManifest → save_stage_artifact(slug="lowcode.codegen")
    6. 进度以步骤事件推送（R-STAGE-24，非 token 流式）
    """
    db_model = await require_artifact(db, project_id, "db.model")
    ui = await optional_artifact(db, project_id, "ui.prototype")

    layout_tables(db_model["tables"])              # ★ 确定性坐标

    ctx = GenContext(
        module_name=module_name or infer_module_name(db_model["model_name"]),
        base_package="com.deloitte.dorbit",
        target=TargetStack(),                      # Vue 3
        model=db_model, menus=(ui or {}).get("menus", []),
    )
    files: list[GeneratedFile] = []
    for table in db_model["tables"]:
        if table["name"] in SKIP_TABLES:           # 便签类、纯关联表可配置跳过
            continue
        files += render_table_files(table, ctx)
        await publish_progress("generating", f"已生成 {table['caption']}")
    files += render_module_files(ctx)              # 启动类/POM/配置

    zip_file_id = await pack_and_store(files, ctx)
    manifest = LowcodeManifest(
        app_title=ctx.app_title, module_name=ctx.module_name,
        base_package=ctx.base_package, target_stack=TargetStack(),
        tables=[t["name"] for t in db_model["tables"]],
        files=files, artifact_file_id=zip_file_id,
        generator_version=GENERATOR_VERSION,
    )
    return await save_stage_artifact(
        db, project_id=project_id, stage_key="lowcode",
        slug="lowcode.codegen", content_json=manifest.model_dump(),
        file_id=zip_file_id, change_note="代码工程生成", source="agent",
    )
```

```python
def build_save_tool(stage_key: str) -> ToolDef:
    """为当前阶段构建 save_stage_artifact 工具。

    input_schema 直接由该阶段产出物的 Pydantic 模型导出，
    使模型在调用工具时就受到结构约束（Claude Agent SDK 无 JSON mode）。
    """
    stage = get_stage(stage_key)
    model = SLUG_SCHEMA_REGISTRY[stage.required_slug]
    return ToolDef(
        name="save_stage_artifact",
        description=(
            f"保存「{stage.name}」阶段的产出物（{stage.required_slug}）。"
            "内容必须符合给定的 schema。校验失败会返回结构化错误，请修正后重试。"
        ),
        input_schema={
            "type": "object",
            "properties": {
                "slug":    {"type": "string", "enum": [a.slug for a in stage.artifacts]},
                "content": model.model_json_schema(),      # ★ 直接复用 Schema
                "change_note": {"type": "string", "description": "本次变更说明"},
            },
            "required": ["slug", "content"],
        },
    )

async def handle_save_stage_artifact(args, ctx) -> dict:
    """工具 handler：校验 → 落库 → 事件。失败返回可修正的结构化错误（R-ART-07）。"""
    try:
        art = await save_stage_artifact(
            ctx.db, project_id=ctx.project_id, conversation_id=ctx.conversation_id,
            stage_key=ctx.stage_key, slug=args["slug"],
            content_json=args["content"], change_note=args.get("change_note"),
            source="agent", run_id=ctx.run_id, user_id=ctx.user_id,
        )
    except ValidationError as e:
        # ★ 不静默丢弃、不强截断；把错误还给模型让它自己修
        return {
            "ok": False,
            "error": "SCHEMA_VALIDATION_FAILED",
            "message": "产出物不符合 schema，请修正后重新调用",
            "details": [
                {"field": ".".join(str(x) for x in err["loc"]),
                 "problem": err["msg"], "expected": err.get("type")}
                for err in e.errors()
            ],
        }
    return {"ok": True, "slug": art.slug, "version": art.current_version,
            "guid": art.guid, "message": f"已保存 {art.title} v{art.current_version}"}

### 8.2 Pinia Store 设计

```typescript
// stores/pipeline.ts
export const usePipelineStore = defineStore('pipeline', () => {
  // 阶段元数据（应用启动拉一次，全局共享）
  const stages = ref<StageMeta[]>([])

  // 当前对话的阶段上下文
  const currentStageKey = ref<StageKey>('interview')
  const currentActions = ref<StageAction[]>([])

  // 产出物：按 stage_key 分组，便于右栏与画布消费
  const artifactsByStage = ref<Record<StageKey, StageArtifact[]>>({})

  // 各阶段就绪状态（派生，见 getter）
  const stageProgress = computed(() =>
    Object.fromEntries(stages.value.map(s => [s.stage_key, {
      ready: (artifactsByStage.value[s.stage_key] ?? [])
               .some(a => a.is_active && a.status === 'ready' && !a.is_archived),
      count: (artifactsByStage.value[s.stage_key] ?? []).length,
      stale: (artifactsByStage.value[s.stage_key] ?? []).some(a => a.is_stale),
    }])))

  const overallProgress = computed(() => {
    const done = Object.values(stageProgress.value).filter(p => p.ready).length
    return { completed: done, total: stages.value.length,
             percent: Math.round(done / stages.value.length * 100) }
  })

  async function switchStage(to: StageKey) { … }   // → POST /conversations/{id}/stage
  function applySseEvent(evt: SseEvent) {
    switch (evt.type) {
      case 'stage_changed':           currentStageKey.value = evt.to
                                      currentActions.value  = evt.actions; break
      case 'stage_artifact_saved':    upsertArtifact(evt); break
      case 'stage_artifact_stale':    markStale(evt); break
    }
  }
  return { stages, currentStageKey, currentActions, artifactsByStage,
           stageProgress, overallProgress, switchStage, applySseEvent }
})
```

> **派生而非存储**（R-DATA-15 / FR-PIPE-09）：阶段进度是 `artifactsByStage` 的 computed，不单独维护状态，不会出现"状态说完成但无产出物"（NFR-C-03）。

### 8.3 安全渲染（R-SEC-04 / FR-UI-14）

原型用 `innerHTML` 直插模型输出，**必须改**：

```
模型回复（markdown）
  → 安全 markdown 渲染（marked + DOMPurify 净化）
  → 结构化卡片单独组件化（StructuredCard.vue 按 schema 渲染，不解析 HTML）
```

- **不得**把 `content_json` 直接作为 HTML 渲染；
- 画布组件（`*Canvas.vue`）**按字段取值渲染**，不用 `v-html`；
- 必须使用 `v-html` 时，内容先过 DOMPurify，且加白名单。

## 9. 第二批模块接口设计（第一批必须完成）

> **R-ENG-11**：第一批设计文档必须包含第二批接口的完整设计。
> **R-ENG-12**：调用方按契约实现后，在功能未实现期间**只依赖"未启用"语义降级**，不得写临时分支。

### 9.1 统一降级约定

**所有第二批接口在本阶段一律返回：**

```jsonc
// HTTP 200（不是 5xx —— 这是"功能未启用"的正常业务语义）
{
  "enabled": false,
  "reason": "NOT_IMPLEMENTED",
  "message": "该能力尚未启用",
  "items": [],           // 空集合，结构符合正式契约
  "total": 0
}
```

**关键设计：`enabled: false` 与"查询无结果"必须可区分**（R-KB-07 的同类要求）：

| 场景 | 响应 | 调用方行为 |
|---|---|---|
| 功能未启用 | `{enabled:false, reason:"NOT_IMPLEMENTED", items:[]}` | 前端隐藏入口或显示"未启用"；编排层跳过注入 |
| 功能已启用但无数据 | `{enabled:true, items:[]}` | 前端显示空态；编排层跳过注入 |
| 功能出错 | `{enabled:true, error:"..."}` | 前端提示；编排层降级 + 告警（R-MOD-03） |

前端通过 `GET /capabilities` 一次拉取各模块的启用状态，**在渲染层决定是否显示入口**，而不是在业务逻辑里写 if。

```jsonc
// GET /capabilities
{
  "pipeline":   { "enabled": true },
  "knowledge":  { "enabled": true, "retrieval_enabled": false },   // ★ Q6a：本体启用，检索不启用
  "assets":     { "enabled": false },
  "market":     { "enabled": false },
  "sharing":    { "enabled": false }
}
```
