四、产品线 A｜AI Agent 工作台功能清单AGENT WORKSPACE

这是当前最活跃的一条线。后端 api/ap_agent（13 个 API 模块 / 18 个 Service），前端有 Vue3 与 Alpine.js 两套。

4.1 后端能力 api/ap_agent

双模式对话引擎 Direct Chat：直接调用 LLM 流式输出（读取最近约 20 条上下文 → SSE 逐 token 推送 → 落库）。 Agent Chat：创建 AgentRun → 准备 workspace/.memory → 调用 Claude Agent SDK 执行 → 工具调用 → 持久化 ToolCall / Reference / 消息。
Agent 工具链与子 Agent 委派 工具集 Read / Write / Edit / Bash / Glob / Grep / WebSearch，配套工具权限回调； subagents.json 定义子 Agent，支持任务拆解与委派。
四级工作空间模型 Workspace → Project → Folder → File，对应 workspaces / projects / folders / files 四组 API， 支持项目树导航、目录管理与文件增删改查。
产出物（Artifact）与引用（Reference） Agent 执行过程产生的文件由 file_watcher.py 自动捕获为产出物；Reference 记录 Agent 引用过的来源，可溯源。
Skill 双轨体系 myskill_service 管理个人/工作区技能，skill_registry_service 提供技能注册中心： 发布、版本管理、权限控制、安装。
三层沙箱执行 Local Shell（Windows 开发）/ Docker（Linux 生产）/ gVisor（高安全）， 由 sandbox_executor.py + docker_shell_backend.py 统一调度，tools/security.py 做命令安全检查。
实时交互机制 SSE 推送 message / tool / todo / artifact / file-tree / done / error 七类事件； 支持 AskUserQuestion——Agent 中途挂起向用户追问，用户回答后继续执行。
文件预览与项目虚拟站点 file_preview_service + preview.py：project_id 即站点标识，可直接预览 Agent 产出的网页/文档。
认证与数据同步 auth_service（JWT + AAD）、disk_sync_service 保持磁盘与数据库状态一致。

4.2 Vue3 客户端 ui/ap_agent_ui

对话工作区 ChatInput / ChatMessages / MessageItem / ToolCallBlock / WelcomeContent —— 流式消息渲染、Markdown 渲染缓存、 工具调用过程可视化（ToolCallBlock）、文件选择器（FileTreePicker）。
三栏 + 预览布局 SidebarLeft（Workspace / Project 树）· MainContent（对话）· SidebarRight · PreviewContent · TopNavigation， 配合 FilePreview / FilePreviewModal 做文件预览。
Skill 市场 SkillListView 浏览 → SkillDetailView 详情 → PublishView 发布 → SkillReviewView 审核 → WorkspaceSkillView 工作区技能； 配套 InstallDialog 安装、PublishDialog 发布、SkillVersionSelector 版本选择、PermissionBadge 权限标识、TagFilter 标签筛选、SearchBar 搜索。
团队协作 TeamManagement / TeamMemberPanel —— 团队成员管理与协作界面。
实时通道与状态管理 Socket.IO（useSocketStore）+ SSE 双通道；Pinia 分域管理： Chat / Project / ProjectWorkspace / Workspace / Skill / Team / AgentApp 共 7 个 Store。

4.3 零构建前端 api/ap_agent/frontend

仅 9 个文件（index.html + 2 CSS + 6 JS），用 CDN 引入 Alpine.js 与 marked， 无 npm、无构建步骤，后端单进程即可提供完整界面 —— 这是「轻量内嵌」路线的实现。

七、产品特点PRODUCT CHARACTERISTICS

这套资产最值得关注的 8 个特点——既是优势，也定义了它当前的形态。

01

双 AI 引擎并行

AI 能力有两套完全独立的实现：Python 侧用 Claude Agent SDK（ap_agent），Java 侧封装 Dify（service_ai）。二者语言、存储、前端、模型供应商全部不同，功能高度重叠。这是当前最需要团队拍板的架构问题。

02

POC 驱动的产品演进

先有 141 个可交互 HTML 原型验证形态，再逐步生产化。原型 → 前端 → 服务的链路可追溯，产品设计意图保留完整（含 BA 各自版本），这在内部研发资产中较为少见。

03

真实业务场景锚定

不是技术演示：原型与技能均围绕丰田汽车税务决算申报、Top200 资产分析、财务共享等真实项目构建，主数据中心覆盖完整的会计核算科目体系（过账码、特别总账标识、税码、WBS）。

04

AI 覆盖软件开发全链路

Java 侧 service_ai 提供 UI 设计生成（UiDsl）、数据库设计生成（Ezdml / SQLParse / OopDsl）、DSL 设计；前端侧 Agent UI 可生成原型、需求分析 Story Map、BPMN 流程、产品路线图。意图是把 AI 用在开发过程本身。

05

低代码 + AI 融合

平台底座自带完整低代码能力（表单设计器、数据表单、报表、业务规则、代码生成 Codegen、Open API），AI 中台作为独立模块嵌入同一套 RBAC / 租户体系，而非外挂系统。

06

Agent 沙箱三层隔离

Local Shell（开发）/ Docker（生产）/ gVisor（高安全）三档可切换，配合命令安全校验与文件监听自动捕获产出物——把「让 Agent 动手」这件事做了工程化约束。

07

Skill 资产化运营

技能被当作可发布、可版本化、可授权、可安装的资产管理：注册中心 + 市场 + 审核 + 权限徽章 + 版本选择器，前端实现了完整的市场闭环。规范上采用标准 Agent Skill（SKILL.md + scripts）。

08

企业级治理能力齐备

多租户 + 租户套餐、OAuth2 全套、操作/登录/API 访问/错误日志四套审计、数据字典与国际化、Nacos 注册与配置中心、Flowable 工作流与 DMN 决策表——平台底座接近开箱即用的企业管理框架。

八、技术特点TECHNICAL CHARACTERISTICS

后端双栈

  • Python：FastAPI + Uvicorn + SQLAlchemy 2.0 异步 + aiomysql + MySQL 8
  • Java：Java 21 + Spring Boot 3.3.1 + Spring Cloud Alibaba + MyBatis-Plus
  • RPC 分工：service_base 用 Dubbo，service_mdm 用 OpenFeign
  • 两套栈通过网关 /dorbit-api/ 与 /dorbit/agent/ 路径分离

前端四套

  • Vue 3.5 + Vite 5 + TS + Element Plus（Agent UI）
  • Vue 3.4 + Vite 5 + avue 3.7.1 + vxe-table（管理端）
  • Alpine.js CDN 零构建单页（ap_agent 内嵌）
  • Vue3 + Tailwind CDN 静态站（两个门户）

实时与流式

  • SSE 为主：7 类事件（message / tool / todo / artifact / file-tree / done / error）
  • Socket.IO 辅助通道（useSocketStore）
  • Agent 中途追问：AskUserQuestion 挂起 / 恢复
  • Markdown 渲染缓存（useMarkdownRenderCache）

数据与中间件

  • MySQL（harness_* 14 表 / ai_* 11 表 / base 68 表含 QRTZ_*）
  • MongoDB、Redis + Redisson、RocketMQ
  • MinIO 对象存储、向量数据库（RAG）
  • DB2 方言脚本（MDM）、EasyExcel 导入导出

部署形态

  • Python 侧：Docker Compose 单容器
  • Java 侧：Nacos 注册 + 配置，Gateway 统一入口
  • 环境：dev / sit 指向 iddcpet{dev,sit}.deloitte.com.cn
  • 路径约定：/dorbit-api/ · /dorbit/admin · /dorbit/agent/

工程与质量

  • 7 个 .gitlab-ci.yml：仅 verify + sonar 两阶段
  • 前端有 vue-tsc --noEmit 与 ESLint，无稳定单测/E2E
  • Java POM 声明 Java 21，CI 使用 JDK 17（不一致）
  • 架构依赖单 worker：事件、锁、会话状态均在进程内

九、三个待团队确认的问题OPEN QUESTIONS

1. 哪套 AI 链路是现行版本？
ap_agent 的 Alpine.js 前端与 ap_agent_ui 的 Vue3 前端，两者 VERSION.md 逐字相同（v1.1.0 / 2026-08-24 / 相同 changelog），但功能重叠。同时 Claude Agent SDK 与 Dify 封装长期并存。需要明确主链路，否则双份维护成本。

2. 展示态 ≠ 实现态。
ap_skills 门户展示 13 个技能，skills/ 中可执行的只有 1 个；ap_poc_center 的多数链接依赖部署时同级挂载。对外汇报时应区分「已实现」与「原型展示」。

3. 上线前的安全与工程门禁。
明文凭据、Docker socket 直挂、资源归属授权、CI 跳过测试等问题已在《AP_Dev_Hub全景分析报告》中单列，本报告不展开。当前状态更适合「安全止血 + 收敛」，而非继续扩展功能。
