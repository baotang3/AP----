## 实习经历改写：勤栈AI+（D.Orbiter）项目

### 已实现（可逐点讲代码）

- Agent 工作台后端：FastAPI + Claude Agent SDK，文件分析 / 代码执行 / 图表报告产出；对话请求与 Agent 运行解耦，RunManager 管理长任务生命周期。
- SSE 事件协议：概念上分「消息、思考、工具起止、待办、追问、产出物、文件树、终态、错误」，代码里实际是 12 个事件名（token / thinking / subagent_token / tool_start / tool_end / todo_updated / question_pending / artifact_generated / file_tree_updated / done / agent_error）。简历写「12 类事件」并按语义分组，与代码一致。
- 回放上限 1 万事件或 8 MiB：这是 run_manager 的实现边界，只能说是保护上限，不能说成吞吐或 SLA。
- Workspace–Project–Folder–File 资源归属链、产出物捕获与引用溯源、工具权限统一回调、危险命令拦截、Docker（runsc/gVisor）沙箱、项目级 Skill 与技能注册中心双轨、JWT 双令牌 + AAD SSO。

### 方案设计 + 原型（简历明确写了「技术方案设计与交互原型」）

- 六阶段流水线：AI 访谈 → 业务流程 → 业务需求 → 原型 → 数据库设计 → 低代码。
- 阶段间靠产出物串联，上一步产出物作为下一步上下文；`store.js` 里 `getPrevOutput` / `saveStepOutput` / `getAllPrevOutputs` 就是这个契约。
- 增量修改机制：意图识别（add / remove / rename / update）+ 定向 patch，只改命中的节点，不整段重生成（`chat.js` 的 `detectIntent` / `locateItem` / `tryPatch`）。
- 真实产物：访谈提纲.pdf、访谈总结、用户故事地图、业务流程地图、DataModels 建模文件（`.dmj`，MySQL、6 张表）、`codegen.zip`（Spring Boot + Vue2 + SQL 代码骨架）、templates.js 里 CRM / 费控 / 资产管理 3 个行业模板。

### 面试时必须说清的边界

- 这套六阶段原型是 HTML + Vue CDN + Tailwind 的高保真交互原型，数据存浏览器 localStorage，`chat.js` 的回复是本地 mock，**没有真实后端服务、没有真实 LLM 调用**。被问「怎么部署的」「并发怎么样」「数据存哪」时直接按原型讲，不要往已实现上靠。
- 「不新增数据表与字段」是设计阶段的复用边界（复用既有 Workspace/Project/Artifact 链路），不要说成已经落库上线。
- 领域模型规模（5 类本体 / 61 实体 / 380 属性）属于设计稿数字，面试时说明是设计文档里的方案约束。
- 简历里没有写 5 类本体 / 61 实体 / 380 属性，避免被当成线上指标追问；如果要提，先说清是设计稿。
