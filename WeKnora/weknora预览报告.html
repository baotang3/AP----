把文档变成会思考的知识资产

WeKnora 是一个开源的、由 LLM 驱动的企业级知识框架，面向文档理解、语义检索与自主推理。 它围绕三条主线组织能力：面向日常查问的 RAG 快速问答、可自主编排检索 / MCP 工具 / 联网搜索的 ReAct Agent，以及把原始文档蒸馏为互相链接的 Markdown 知识库的 Wiki 模式。

MCP INTEGRATION

MCP 集成：两个方向

MCP（Model Context Protocol）在 WeKnora 里是双向的：既可以让 WeKnora 的 Agent 去调用外部 MCP 工具（客户端方向）， 也可以把 WeKnora 的知识库能力暴露给 Claude Desktop / Cursor / 其他 AI Agent 使用（服务端方向）。

方向 A：在 设置 → MCP 服务 里登记外部 MCP Server，WeKnora 的 Agent 在 ReAct 推理时即可调用它们的工具 —— 相当于给知识库问答插上「外部世界的操作能力」。

能实现什么

  • 让问答 Agent 直接查询业务数据库、调用内部微服务
  • 接入代码执行 / 数据分析类 MCP（Code Interpreter 等）
  • 接入外部搜索、地图、工单、CRM 等第三方能力
  • 远程 MCP 服务可用 OAuth2 鉴权，支持会话中途发起 OAuth
  • 用 @MCP 提及在单轮对话中限定可用工具范围
  • 危险工具可开启人工审核，执行前中断等待确认

配置要素

传输方式SSE（推荐，流式体验）/ HTTP Streamable（标准兼容）/ Stdio（本地 uvx·npx 命令）
连接信息URL 或启动命令 + 参数 + 环境变量
认证API Key / Bearer Token / OAuth2
高级timeout、retry_count、retry_delay
入口前端 设置 → MCP 服务，支持启停 / 测试 / 编辑 / 删除
连接测试 API
# 测试连通性，返回可用工具清单（含输入 schema）与资源列表
POST /api/v1/mcp-services/{id}/test

# 启停服务
PUT  /api/v1/mcp-services/{id}
人工审核（危险工具）
# 列出 / 设置某工具是否需要人工审核
GET /api/v1/mcp-services/:id/tool-approvals
PUT /api/v1/mcp-services/:id/tool-approvals/:tool_name

# 审批卡片提交结果
POST /api/v1/agent/tool-approvals/:pending_id
{ "decision": "approve" | "reject" }
审核机制要点：Agent 即将调用已打标工具时推送 tool_approval_required 事件，前端弹出审批卡片（可编辑 JSON 参数）； 通过或拒绝后恢复执行，拒绝时把错误信息返回给模型、不会真的调用远端。默认等待 10 分钟超时视为拒绝， 可用 WEKNORA_AGENT_TOOL_APPROVAL_TIMEOUT=600 调整。多副本部署时依赖 Redis Pub/Sub 跨实例唤醒等待者。
方向 B：项目自带一个 Python 实现的 weknora-mcp-server（PyPI 包名 tencent-weknora-mcp）， 把 WeKnora 的知识管理 API 包装成 28 个 MCP 工具。任何支持 MCP 的宿主（Claude Desktop、Cursor、KiloCode、DSH…）接入后， 就能用自然语言驱动知识库：检索、导入、问答、Agent 对话、Wiki 浏览。

集成后可以实现

  • 知识库检索 —— hybrid_search 向量 + 关键词混合搜索，可直接回答「根据我的知识库…」
  • 文档导入 —— 从本地文件或 URL 一键灌入知识库
  • 知识管理 —— 列出 / 查看 / 删除知识条目与文本分块
  • RAG 问答 —— chat 走检索增强流水线并返回带引用的答案
  • Agent 对话 —— agent_chat 触发 WeKnora 的 ReAct Agent 做多步推理
  • Wiki 浏览 —— wiki_search / wiki_read_page / wiki_index_view
  • 空间与模型管理 —— 创建空间、知识库、模型配置、会话

NOTES

注意事项与安全建议

部署安全

  • 从 v0.1.3 起内置登录认证；生产环境建议部署在内网/私有网络，不要直接暴露公网
  • 配置防火墙规则与访问控制，定期升级获取安全补丁
  • API Key / MCP 凭据落库时 AES-256-GCM 加密，但仍需妥善保管数据库访问权限
  • MCP 建议单独创建最小权限的 API Key 并定期轮换
  • 内置 MCP 服务的 URL / 认证信息在前端会被隐藏，但数据库原始数据仍存在

MCP 使用要点

  • 传输方式优先 SSE（流式体验），标准兼容选 HTTP Streamable，本地调试用 Stdio
  • 内置 MCP 服务仅支持 sse 与 http-streamable，stdio 在服务端被禁用
  • 公网/第三方服务适当提高 retry_count 与 retry_delay，避免间歇超时中断 Agent
  • 危险工具开启「需人工审核」，审批等待状态保存在进程内存，多副本需 Redis 支撑
  • 内置 MCP 服务需通过 SQL 直插数据库并设置 is_builtin = true，不可在前端编辑删除
